{\Large \bf ABSTRACT}
\vspace{10pt}
\end{center}

Service Function Chaining (SFC) in Software-Defined Networking (SDN) environments enables the dynamic composition of Virtual Network Functions (VNFs) to deliver complex network services. However, practical SFC deployments in geo-distributed data center networks (DCNs) face severe challenges, including latency accumulation, resource fragmentation, and the non-trivial overhead of migrations under dynamic traffic conditions. The adoption of programmable data planes based on Segment Routing over IPv6 (SRv6) and P4 switches introduces fine-grained, source-routed traffic steering but imposes strict hardware limitations, most notably the Maximum Segment Depth (MSD), which defines the strict upper limit of parsing capabilities on an ASIC.

This thesis proposes \textbf{3S-COM} (Smart, Scalable, Secure), a fully closed-loop orchestration architecture that jointly optimizes VNF placement and proactive migration across a geo-distributed backbone network simulated and emulated over 10 primary locations in Vietnam. The core of the system is the Joint Optimization of VNF Placement and Proactive Migration (JO-VPPM) framework, integrated with a hybrid Heuristic/DGRL runtime and a Make-Before-Break migration controller.

Moving beyond naive heuristics and basic Deep Reinforcement Learning (DRL), this research architects a robust Deep Graph Reinforcement Learning (DGRL) agent powered by Graph Attention Networks (GAT). A critical innovation lies in modeling the network with a Static Adjacency Matrix, Invalid Action Masking for hard MSD safety, and an Adaptive Lagrangian Penalty for soft SLA control. Experimental results demonstrate that JO-VPPM significantly outperforms traditional Greedy and Decoupled AI baselines under stress, while the Hardware-in-the-Loop testbed validates the practical control loop using MicroK8s, Tekton, Mininet BMv2 P4 switches, SRv6 steering, and explicit Smart Admission Control through \texttt{409 NO\_SAFE\_ACTION} when no hardware-safe action exists.

\chapter{Introduction}
\label{chap:introduction}

\section{Motivation and Background}
The exponential surge in data traffic driven by emerging paradigms such as 5G/6G mobile networks, the Internet of Things (IoT), autonomous vehicles, and high-fidelity video streaming services has placed unprecedented pressure on global telecommunication infrastructures. This digital explosion mandates network architectures that are not only high-bandwidth but also highly agile, scalable, and dynamically programmable. To meet these stringent requirements, the industry has aggressively transitioned from monolithic, proprietary hardware appliances toward Software-Defined Networking (SDN) and Network Function Virtualization (NFV). SDN decouples the control plane from the data plane to provide centralized intelligence and programmability, while NFV abstracts physical network appliances into Virtual Network Functions (VNFs)—such as firewalls, intrusion detection systems (IDS), and deep packet inspectors (DPI)—running on commodity off-the-shelf (COTS) servers. 

The concatenation of these VNFs to deliver complex end-to-end network services is known as Service Function Chaining (SFC). A typical SFC defines the exact sequence of security and processing functions a traffic flow must traverse before reaching its destination. While SFC dramatically enhances service agility, its deployment across geo-distributed data center networks (DCNs), such as long-haul backbone networks spanning an entire nation, introduces severe operational bottlenecks. End-to-end latency accumulates precipitously across vast geographical distances, computational and memory resources become fragmented across distributed edge and core hubs, and the migration of VNFs during unexpected traffic influxes incurs massive state-transfer overheads.

Simultaneously, the evolution of programmable data-planes has revolutionized traffic steering capabilities. Segment Routing over IPv6 (SRv6) has rapidly emerged as the de-facto standard for modern backbone routing. Unlike traditional IP routing which requires maintaining per-flow state across every intermediate switch, SRv6 implements source routing. It encodes the entire routing path and the VNF processing sequence directly into the IPv6 packet header as a stack of Segment Identifiers (SIDs). This allows intermediate P4-programmable switches to forward packets statelessly at line-rate simply by executing the instructions embedded in the packet header.

However, a critical and often overlooked phenomenon threatens the viability of SRv6-enabled SFC: the hardware limitations of modern switching Application-Specific Integrated Circuits (ASICs). The most prominent of these constraints is the Maximum Segment Depth (MSD), which defines the strict physical upper boundary on the number of SIDs an ASIC can parse within a single packet header. When an SFC demands a complex routing path requiring an SID stack that exceeds the MSD of any switch along its route, the hardware simply cannot parse the packet. This results in catastrophic network failures such as packet drops, infinite recirculation loops, and severe latency spikes. 

Despite this imminent threat, existing network orchestration algorithms—ranging from traditional Integer Linear Programming (ILP) and greedy heuristics to modern standard Deep Reinforcement Learning (DRL) agents—habitually abstract the network as an idealized mathematical graph. They either completely ignore the MSD constraint or naively assign it a soft penalty. This fundamental disconnect between high-level orchestration logic and low-level data-plane physics inevitably generates routing solutions that are theoretically optimal in simulation but functionally destructive when deployed to production hardware like the Intel Tofino switches.

\section{Problem Statement}
Given a geo-distributed backbone network, mathematically modeled as a topological graph where nodes represent computational data centers interconnected by high-latency transmission links, the fundamental problem is two-fold: First, how to dynamically place a sequence of VNFs to satisfy incoming SFC requests; and second, how to proactively migrate existing VNFs to mitigate impending traffic congestion. 

The objective is to design an intelligent, closed-loop orchestrator that jointly optimizes VNF placement and proactive migration (JO-VPPM) to strictly minimize end-to-end service latency and operational switching costs. Crucially, this optimization must be strictly constrained by the hardware realities of the data plane. The framework must absolutely guarantee that no computed routing path generates an SRv6 stack that violates the Maximum Segment Depth (MSD) limitation of any traversed programmable switch. 

Solving this requires an orchestration intelligence capable of operating continuously in near real-time, predicting short-term traffic spikes, and fundamentally interpreting the spatial topography of the network to balance resource loads across geographically distant data centers securely.

\section{Highlight of Contributions}
To address the critical divergence between AI-driven orchestration and rigid data-plane physics, this thesis proposes the \textbf{3S-COM} (Smart, Scalable, Secure) architecture. We introduce a novel Deep Graph Reinforcement Learning orchestration framework specifically tailored for geo-distributed backbone environments. The key contributions of this research include:

\begin{itemize}
    \item \textbf{Hardware-Constrained Mathematical Modeling:} A rigorous formulation of the Joint Optimization of VNF Placement and Proactive Migration (JO-VPPM) problem. The model natively embeds SRv6 MSD physical limitations as hard boundaries: an unsafe SID stack is rejected before enforcement rather than rescued by Binding SID compression.
    \item \textbf{Deep Graph Reinforcement Learning (DGRL):} The development of a topology-aware reinforcement learning agent powered by Graph Attention Networks (GAT). We identify that standard Multi-Layer Perceptrons fail to comprehend geographical routing logic, and demonstrate how utilizing a Static Adjacency Matrix within the GAT preserves the fundamental eigenvalues necessary for the Critic network's convergence.
    \item \textbf{Hybrid Orchestration with Smart Admission Control:} The implementation of a Hysteresis Gate that uses inexpensive heuristic decisions during stable load and activates MaskablePPO/DGRL under stress or alert conditions. If Action Masking removes every feasible placement-routing pair, the controller returns \texttt{409 NO\_SAFE\_ACTION}, treating rejection as a safety-preserving admission decision rather than a runtime failure.
    \item \textbf{Hardware-in-the-Loop Testbed:} A 10-node Vietnam Backbone testbed combining MicroK8s VNF orchestration, Tekton lifecycle pipelines, L2-transparent Mininet-to-Kubernetes connectivity, CPU-pinned BMv2 P4 switches, and REST-driven SRv6 steering. The testbed implements the control-plane sequence required for Make-Before-Break migration, while final continuity validation is reserved for packet-level evidence.
\end{itemize}

\chapter{Background and Related Work}
\label{chap:background_related}

This chapter establishes the theoretical foundations of the technologies integrated within the 3S-COM framework and provides a critical survey of existing orchestration methodologies. We begin by examining the evolution of Software-Defined Networking (SDN) and Network Function Virtualization (NFV), followed by a deep dive into the physical constraints of Segment Routing over IPv6 (SRv6). Subsequently, we explore the paradigms of Deep Reinforcement Learning (DRL) and Graph Neural Networks (GNN). Finally, we identify the specific research gaps that motivate the development of the JO-VPPM framework.

\section{Technical Background}
\label{sec:background}

\subsection{Network Function Virtualization (NFV) and SFC}
The transition from proprietary, hardware-centric network appliances (Middleboxes) to software-based \textbf{Network Function Virtualization (NFV)} has fundamentally altered service delivery models in telecommunications. NFV enables the instantiation of Virtual Network Functions (VNFs)—such as firewalls, load balancers, and deep packet inspectors—on commodity off-the-shelf (COTS) servers. 

The ETSI NFV Architectural Framework defines three key functional blocks: the \textbf{NFV Infrastructure (NFVI)}, the \textbf{Virtual Network Functions (VNFs)}, and the \textbf{NFV Management and Orchestration (MANO)} stack. The decoupling of functional logic from physical hardware allows for rapid service deployment and elastic scaling, significantly reducing Capital Expenditure (CAPEX) and Operational Expenditure (OPEX).

To provide a comprehensive end-to-end service, these VNFs must be organized into a specific sequence known as a \textbf{Service Function Chain (SFC)} \cite{wang2021drl}. As defined in RFC 7665, an SFC specifies the set of virtual network functions and their strict execution order to be applied to a specific traffic flow. For instance, in a 5G core network, an enterprise traffic flow might traverse a Firewall, followed by an Intrusion Detection System (IDS), and finally a Load Balancer.

    \centering
    \safeincludegraphics[width=0.8\textwidth]{thesis/figs/ETSI-MANO.jpg}
    \vspace{0.5cm}
    \caption{The ETSI NFV Reference Architecture showing the decoupling of hardware/software layers and the MANO orchestrator.}

The core challenge in SFC orchestration lies in the \textbf{Joint Optimization of VNF Placement and Routing}. In geo-distributed data center networks (DCNs), this problem is NP-hard. The orchestrator must select optimal data center nodes to host each VNF while ensuring the routing path minimizes propagation latency over a high-latency backbone (e.g., across 10 Vietnamese provinces). Furthermore, it must manage uneven resource distribution and the highly dynamic nature of incoming service requests, particularly in "Elephant" vs "Mouse" traffic scenarios.

\subsection{SRv6 and Network Programming (RFC 8986)}
Segment Routing over IPv6 (SRv6) is a modern source-routing paradigm that leverages the IPv6 data plane. Unlike traditional MPLS-TE, which relies on complex signaling protocols (like RSVP-TE or LDP), SRv6 encodes the network path and service instructions directly into the IPv6 header as a ordered list of \textbf{Segment Identifiers (SIDs)} \cite{filsfils2015segment}. 

The \textbf{Segment Routing Header (SRH)}, as defined in RFC 8754, carries the sequence of SIDs representing the path segments and VNF behaviors. According to the "Network Programming" model (RFC 8986), a SID is not just an IP address but a combination of \textit{Locator:Function:Args}.
\begin{itemize}
    \item \textbf{Locator:} The address of the node that executes the function.
    \item \textbf{Function:} The specific opcode (e.g., End, End.X, End.DX2) to be executed on the packet.
\end{itemize}

\begin{figure}[H]
    \centering
    \safeincludegraphics[width=0.8\textwidth]{thesis/figs/SRv6.png}
    \vspace{0.5cm}
    \caption{The SRv6 Segment Routing Header (SRH) structure including the Segment List and the Routing Extension Header.}
    \label{fig:srv6_header}
\end{figure}

SRv6 enables a "Stateless Data Plane," where intermediate routers do not need to maintain flow-specific state, greatly enhancing network scalability. However, this efficiency comes at the cost of significantly increased header size, as each SID adds 128-bits (16 bytes) to the packet overhead.

\subsection{Hardware Parsing Constraints: Maximum Segment Depth (MSD)}
While SRv6 is highly flexible in software, its implementation on high-speed programmable hardware faces rigorous physical boundaries. Modern ASICs follow the \textbf{PISA (Protocol-Independent Switch Architecture)} model, which utilizes a pipeline of match-action stages. 

To process an SRv6 packet, the switch's \textbf{Parser} must extract and examine the SID stack in the header. The \textbf{Maximum Segment Depth (MSD)} represents the maximum number of SIDs that a switch can successfully parse and process from a single IPv6 header in a single clock cycle \cite{qiu2024sfcplanner}.

\begin{figure}[H]
    \centering
    \safeincludegraphics[width=0.8\textwidth]{thesis/figs/The-PISA-architecture.png}
    \vspace{0.5cm}
    \caption{The PISA Switch Architecture highlighting the Parser stage and the SID parsing bottleneck.}
    \label{fig:pisa_arch}
\end{figure}

If the number of SIDs in an SFC exceeds the hardware MSD, the switch must either drop the packet or perform ``Recirculation,'' passing the packet through the pipeline multiple times \cite{xiang2019p4sc}. Recirculation effectively halves the switch's throughput and increases latency, rendering it unusable for carrier-grade URLLC (Ultra-Reliable Low-Latency Communication) 5G services. Some SRv6 designs introduce Binding SIDs to compress or hide long segment lists; however, relying on Binding SIDs as a ``rescue'' mechanism obscures the critical role of the orchestrator's spatial awareness and undermines the scientific contribution of Action Masking. This thesis therefore deliberately excludes BSID from the critical path: JO-VPPM treats MSD as a true hard physical boundary where invalid actions are masked before selection, and requests with no hardware-safe action are rejected through Smart Admission Control (HTTP \texttt{409 NO\_SAFE\_ACTION}).

\subsection{Deep Graph Reinforcement Learning (DGRL)}
To address the dynamic and complex nature of geo-distributed orchestration, this research employs \textbf{Deep Reinforcement Learning (DRL)}. The orchestration problem is modeled as a \textbf{Markov Decision Process (MDP)}, defined by the tuple $(\mathcal{S}, \mathcal{A}, \mathcal{P}, \mathcal{R}, \gamma)$, where $\mathcal{S}$ is the state space, $\mathcal{A}$ is the action space, $\mathcal{P}$ is the transition probability, $\mathcal{R}$ is the reward function, and $\gamma$ is the discount factor.

We specifically utilize the \textbf{Proximal Policy Optimization (PPO)} algorithm \cite{schulman2017proximal}, which ensures training stability by clipping the objective function:
\begin{equation}
L^{CLIP}(\theta) = \hat{\mathbb{E}}_t \left[ \min(r_t(\theta)\hat{A}_t, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat{A}_t) \right]
\end{equation}

However, standard policy networks based on Multi-Layer Perceptrons (MLP) suffer from "topology blindness," as they treat network state representations as flat feature vectors. To overcome this, we utilize \textbf{Graph Attention Networks (GAT)} \cite{velivckovic2017graph}. GAT allows the agent to explicitly model the substrate network as a graph $\mathcal{G} = (\mathcal{V}, \mathcal{E})$, where each vertex represents a data center and edges represent physical links. 

The core of GAT is the attention mechanism, which computes the importance of node $j$'s features to node $i$:
\begin{equation}
e_{ij} = \text{LeakyReLU}\left(\vec{a}^T [\mathbf{W}\vec{h}_i || \mathbf{W}\vec{h}_j]\right)
\end{equation}
By utilizing multi-head self-attention, the agent can weigh the importance of neighboring nodes' resources (e.g., CPU, Memory, available MSD) relative to its current placement decision. This graph-aware perception is essential for understanding the spatial implications of VNF placement on end-to-end latency and hardware feasibility.

\section{Related Work}
\label{sec:related_work}
The problem of SFC orchestration has been extensively studied, evolving from classical optimization to modern machine learning paradigms. We categorize existing literature into three functional domains.

\subsection{Classical Optimization and Heuristics}
Traditional approaches often formulate VNF placement as an \textbf{Integer Linear Programming (ILP)} problem or a variation of the Multi-Dimensional Knapsack Problem. While ILP can find mathematically optimal solutions for small topologies, its computational complexity is NP-hard. 

Heuristic algorithms, such as First-Fit, Best-Fit, or Greedy-based strategies, offer faster execution but frequently fall into local optima. These "Short-sighted" strategies fail to manage long-term resource fragmentation or accommodate proactive migration needs in dynamic 5G environments where traffic flows fluctuate rapidly.

\subsection{DRL-based SFC Orchestration}
Recent work has leveraged DRL to automate SFC placement. Wang et al. \cite{wang2021drl} proposed DRL-SFCP, an adaptive placement strategy using PPO. Similarly, Wu et al. \cite{wu2025drl} demonstrated a fast joint mapping approach using DRL, and Qu et al. \cite{qu2021reliable} proposed a reliable deployment method. Some models focus on delay guarantees through VNF parallelization \cite{liu2025delay} rather than proactive migration. However, these paradigms typically operate under the assumption of an ``ideal'' data plane with infinite parsing capacity. They treat hardware constraints as soft penalties in the reward function, which is insufficient for production P4 switches where MSD violations cause binary failure (packet loss).

\subsection{Graph-Aware and Hardware-Aware Approaches}
The integration of Graph Neural Networks with RL is a burgeoning field. Pei et al. \cite{pei2025graph} utilized Graph Pointer Networks (GPN) for network embedding, demonstrating the superiority of topological awareness. In the domain of SRv6, Qiu et al. \cite{qiu2024sfcplanner} introduced SFCPlanner, an online planning approach focusing on SRv6 flow steering. 

Despite these advances, there is a distinct lack of research that jointly optimizes placement and \textbf{proactive migration} while strictly adhering to \textbf{binary hardware limits (MSD)}. A recent survey by Zhang and Wang \cite{zhang2025sfcmigration} confirms that existing SFC migration strategies remain predominantly reactive, and Zhai et al. \cite{zhai2023migration} proposed failure-prediction-based migration but without MSD awareness. Most models either ignore migration costs or fail to perceive the graph spectral stability required for GNN convergence in dynamic environments.

\subsection{Network Model}
We model the substrate network as an undirected graph $\mathcal{G}_s = (\mathcal{N}, \mathcal{E})$. Each node $n \in \mathcal{N}$ represents a Data Center governed by finite resources. Unlike flat DC models, our nodes possess a hardware limit ($MSD_n$) characterizing the parsing depth of the local SRv6-enabled ingress switch.

The objective function of JO-VPPM minimizes the weighted total cost:
\begin{equation}
\min C_{\text{total}} = \sum_{r \in R} \left( \alpha L_{\text{total}} + \beta S_{\text{cost}} + \gamma E_{\text{cost}} \right)
\end{equation}
where $L_{\text{total}}$ is total latency and $S_{\text{cost}}$ is the switching cost of migration.

\textbf{SRv6 Hard Constraint:}
A decision is feasible if and only if:
\begin{equation}
\sum_{k=1}^{\mathcal{J}_r} \text{SID}_k \le MSD_n, \quad \forall n \in \text{path}_r
\end{equation}

\section{Research Gaps}
\label{sec:gaps}
Despite the growing interest in leveraging AI for network orchestration, our analysis of the current literature reveals four critical gaps that remain unaddressed:

\begin{enumerate}[label=RG\arabic*., leftmargin=*, nosep]
    \item \textbf{Hardware - Data Plane Physical Disconnect:} Most existing Deep Reinforcement Learning (DRL) frameworks for SFC orchestration treat hardware processing limits as soft penalties in the reward function. In production-grade programmable switches (e.g., Intel Tofino), the Maximum Segment Depth (MSD) is a non-negotiable physical boundary. Treating it as a "soft penalty" rather than a hard constraint leads to invalid paths that cause immediate packet drops in actual deployments.

    \item \textbf{Reactive vs. Proactive Orchestration in Geo-Distributed Networks:} Current VNF management strategy is predominantly reactive—triggered only after service degradation or resource saturation has already occurred. In geo-distributed networks, the propagation latency of control-plane signaling makes reactive scaling insufficient for high-mobility traffic. There is a lack of integrated pipelines that combine short-term traffic forecasting (e.g., via Bi-GRU) with proactive migration logic.

    \item \textbf{Topology-Blind AI Architectures:} Standard DRL agents utilizing Multi-Layer Perceptrons (MLP) treat network states as unstructured feature vectors. These "topology-blind" agents fail to comprehend the geographical and topological relations of the substrate network, leading to inefficient routing and sub-optimal load balancing between distant core hubs.

    \item \textbf{Training Instability in Graph-Based RL:} When applying Graph Neural Networks (GNNs) to reinforcement learning, the dynamic nature of adjacency matrices often causes the agent's gradient to oscillate or the policy's explained variance to collapse. A stable representation that preserves the graph's spectral integrity while remaining hardware-aware is missing from current research.
\end{enumerate}

\section{Research Questions}
\label{sec:rqs}
Driven by the identified gaps, this thesis seeks to answer the following research questions:

\begin{enumerate}[label=RQ\arabic*., leftmargin=*, nosep]
    \item How can the SRv6 Maximum Segment Depth (MSD) physical limit be natively integrated as a hard hardware constraint within a Reinforcement Learning agent to guarantee 100\% packet parsing feasibility on programmable switches?
    
    \item In what way does a Graph Attention Network (GAT) architecture with a Static Adjacency matrix enhance the orchestrator's awareness of geo-distributed topologies compared to standard topology-blind Deep Reinforcement Learning agents?
    
    \item How does the integration of time-series traffic forecasting within a closed-loop orchestration pipeline enable proactive migration to outperform traditional reactive mechanisms in terms of service continuity and resource utilization?
    
    \item To what extent can the proposed JO-VPPM framework achieve measurable performance gains in acceptance ratio and latency whilst strictly adhering to hardware limitations compared to Integer Linear Programming (ILP) and heuristic baselines?
\end{enumerate}

To address the NP-hard nature of VNF placement under hardware-level data plane constraints, we establish a rigorous modeling of the substrate network and the service requests before deriving the Deep Graph Reinforcement Learning solution.

\section{Problem Formalization and Network Modeling}
\label{sec:math_modeling}
The orchestration of Service Function Chains (SFC) in a geo-distributed environment involves mapping logical service requests onto a physical substrate while ensuring that both computing and networking constraints are strictly satisfied.

\subsection{The Substrate Network Model}
We represent the substrate network as a weighted undirected graph $\mathcal{G}_s = (\mathcal{V}_s, \mathcal{E}_s)$, where $\mathcal{V}_s = \{v_1, v_2, \dots, v_n\}$ is the set of data center nodes ($n=10$ in this research) and $\mathcal{E}_s$ is the set of physical links connecting them. 

Each node $v \in \mathcal{V}_s$ is characterized by a multi-dimensional resource capacity vector $\mathbf{C}_v = [C_v^{cpu}, C_v^{ram}, C_v^{msd}]$. 
\begin{itemize}
    \item $C_v^{cpu} \in \mathbb{R}^+$: Total compute capacity in standardized units.
    \item $C_v^{ram} \in \mathbb{R}^+$: Total transient memory capacity.
    \item $C_v^{msd} \in \mathbb{Z}^+$: The \textbf{Maximum Segment Depth (MSD)} limit of the ingress switch at node $v$. This represents the hard physical boundary of the PISA-based parser, defined as the maximum number of 128-bit SIDs that can be processed in a single clock cycle.
\end{itemize}

The set of edges $\mathcal{E}_s$ is associated with a latency matrix $\mathbf{L} \in \mathbb{R}^{n \times n}$, where each element $L_{ij}$ represents the propagation delay between node $i$ and node $j$ calculated via the Haversine geodesic formula:
\begin{equation}
d = 2R \arcsin \left( \sqrt{\sin^2 \left( \frac{\phi_2 - \phi_1}{2} \right) + \cos \phi_1 \cos \phi_2 \sin^2 \left( \frac{\lambda_2 - \lambda_1}{2} \right)} \right)
\end{equation}
The propagation latency is then derived as $l_{ij} = d/v_{fiber} + p_{delay}$, where $v_{fiber}$ is the velocity of light in fiber optics and $p_{delay}$ is the node-specific processing delay.

\subsection{The SFC Request Model}
A service request $r \in \mathcal{R}$ is modeled as an ordered sequence of Virtual Network Functions (VNFs), defined by $\mathcal{G}_r = (\mathcal{F}_r, \mathcal{L}_r)$, where $\mathcal{F}_r = \{f_1, f_2, \dots, f_m\}$ is the set of functions and $\mathcal{L}_r$ represents the logical links between them.

For every request $r$, a resource demand vector $\mathbf{D}_r = [d_r^{cpu}, d_r^{ram}, d_r^{msd}]$ is specified. The parameter $d_r^{msd}$ is of particular importance, as it denotes the number of SRv6 Segment Identifiers (SIDs) required to encapsulate the specific function's behavior (e.g., \textit{End.DX2} or \textit{End.AM}).

The orchestration task is define as finding a mapping function $\mathcal{M}: \mathcal{F}_r \to \mathcal{V}_s$ such that:
\begin{equation}
\mathcal{M}(f_i) = v_j, \quad \forall f_i \in \mathcal{F}_r, v_j \in \mathcal{V}_s
\end{equation}
Simultaneously, the routing sub-problem must find a physical path $P_{ij} \subset \mathcal{E}_s$ for every logical link $(f_i, f_{i+1}) \in \mathcal{L}_r$.

\subsection{Proactive Migration: Stateless Flow Steering (Make-Before-Break)}
A fundamental innovation of the JO-VPPM framework is its approach to proactive migration \cite{moshiri2026proactive}. We define \textbf{Proactive Migration} not merely as a reactive Admission Control mechanism (which simply blocks new VNFs on saturated nodes), but as a strict \textit{Make-Before-Break} stateless flow steering procedure. The migration of an existing SFC to alleviate impending congestion follows a precise 3-step orchestration sequence:

\begin{enumerate}
    \item \textbf{Scale-Out (Make):} The orchestrator instantiates a new replica of the target VNF on the destination node selected by the AI agent, while the original VNF continues processing traffic without interruption.
    \item \textbf{Stateless Flow Steering (Steer):} Because SRv6 enforces path instructions at the ingress node, the SDN Controller updates the ingress P4 switch to encapsulate incoming packets with the new SRv6 SID list pointing to the new VNF replica. The data plane shifts the flow seamlessly without requiring any state synchronization between the old and new instances.
    \item \textbf{Terminate (Break):} The deletion of the old VNF instance (Break) is triggered \textbf{only after} the SDN Controller confirms that the new SRv6 routing rules have been fully installed (\texttt{confirm\_steer\_done=true}). Once this confirmation is received and the old VNF's queues are drained (verified via the Controller's flow counter), the orchestrator terminates the original VNF replica, freeing resources on the congested node. The ``Make-Before-Break'' paradigm would be entirely invalidated if the old Pod were deleted simultaneously with or before the flow steering.
\end{enumerate}

This mechanism is designed to support zero-downtime migration, a critical requirement for Carrier-Grade 5G URLLC services, by leveraging the inherently stateless nature of SRv6 source routing. A final zero-downtime claim requires TCP sequence/acknowledgement evidence showing that the old SRv6 path remains fully active until the new data path is successfully rewritten.

\subsection{Queuing Latency Model: M/G/1 Pollaczek-Khinchine}
Traditional orchestration models often rely on the M/M/1 queuing model \cite{bertsekas1992data}, which assumes exponentially distributed service times. However, modern telecom traffic is highly bursty and exhibits Heavy-Tail distributions (e.g., Pareto), rendering M/M/1 highly inaccurate under high loads.

We utilize the \textbf{M/G/1 (Pollaczek-Khinchine)} model to accurately capture the queuing delay at each data center node. The expected waiting time in queue $W_q$ is given by:
\begin{equation}
W_q = \frac{\lambda \mathbb{E}[S^2]}{2(1-\rho)}
\label{eq:mg1}
\end{equation}

Where:
\begin{itemize}
    \item $\lambda$: Arrival rate of incoming service flows to the node.
    \item $\rho = \lambda \mathbb{E}[S]$: Resource utilization factor (e.g., CPU load, $\rho \in [0,1)$).
    \item $\mathbb{E}[S^2]$: The second moment of the service time $S$, computed as $\text{Var}(S) + (\mathbb{E}[S])^2$.
\end{itemize}

Unlike M/M/1 where $\text{Var}(S) = (\mathbb{E}[S])^2$, the M/G/1 model natively integrates the variance of general traffic distributions. For Heavy-Tail traffic where the coefficient of variation $C_v^2 = \text{Var}(S)/(\mathbb{E}[S])^2$ is large (e.g., $C_v^2 = 3.0$ for Elephant flows), the term $\mathbb{E}[S^2]$ becomes dominant. Consequently, as the CPU utilization approaches saturation ($\rho \to 1$), the queuing latency $W_q$ diverges to infinity \textit{much more violently} than predicted by M/M/1. This mathematical reality precisely explains the ``Congestion Collapse'' phenomenon observed at centralized nodes when utilizing traditional Greedy algorithms, and provides the theoretical justification for JO-VPPM's necessity to proactively disperse traffic across geographically distributed nodes.

\subsection{Implicit Bandwidth Management via SDN Controller}
To prevent the \textit{Curse of Dimensionality} and avoid shattering the convergence of the pre-trained DRL model weights, Link Bandwidth is \textbf{not} explicitly included in the agent's Observation Space. Including per-link bandwidth as observable features would expand the deployed state vector from $\mathbb{R}^{N \times 6 + 13}$ to $\mathbb{R}^{N \times 6 + 13 + |\mathcal{E}|}$, fundamentally altering the policy network's input structure and invalidating all trained parameters.

Instead, bandwidth is reserved for the SDN Controller layer rather than being encoded in the deployed DRL observation. In the current prototype, controller-side enforcement focuses on SRv6 steering visibility and MSD-safe admission; explicit link-utilization-based rejection is left as an extension. This architectural decision separates \textit{what the AI optimizes} (placement topology) from \textit{what the infrastructure enforces} (physical link limits), following the principle of separation of concerns in distributed systems.

\subsection{Mathematical Formalization: Hard vs. Soft Constraints in Safe RL}
The JO-VPPM framework distinguishes itself by treating hardware limits as hard boundaries rather than soft penalties, demonstrating a deep integration of \textbf{Safe Reinforcement Learning} principles \cite{ray2019benchmarking, ma2022conservative}. We explicitly bifurcate our constraint handling mechanisms:
\begin{enumerate}
    \item \textbf{Invalid Action Masking (Hard Constraints):} Physical limitations like CPU capacity and Maximum Segment Depth (MSD) cannot be violated without causing immediate data-plane failure. These are enforced rigidly via a masking layer before the policy's softmax activation, zeroing out the probability of any invalid topological placement.
    \item \textbf{Adaptive Lagrangian Penalty (Soft Constraints):} Service Level Agreements (e.g., End-to-End Latency) are treated as soft constraints. Violating an SLA degrades user experience but does not crash the switch. These are managed dynamically via a Lagrangian multiplier $\lambda$, which gently steers the agent's reward surface rather than artificially restricting its exploration space.
\end{enumerate} 

\textbf{C1: Computing Resource Constraint.} The total CPU and RAM consumed at any node $v$ must not exceed its capacity:
\begin{equation}
\sum_{r \in \mathcal{R}_{active}} \sum_{f_i \in \mathcal{F}_r} x_{v, f_i} \cdot d_r^{cpu} \le C_v^{cpu}, \quad \forall v \in \mathcal{V}_s
\end{equation}
where $x_{v, f_i} \in \{0,1\}$ is a binary variable indicating if VNF $f_i$ is placed on node $v$.

\textbf{C2: SRv6 MSD Hard Constraint.} For every packet traversing the SFC path, the depth of the SID stack at the ingress of any switch node $v$ must be less than or equal to the switch's MSD capability:
\begin{equation}
\mathcal{S}_{depth}(r, v) \le C_v^{msd}, \quad \forall v \in \text{Path}(r)
\end{equation}
Unlike CPU, which is subtractive, the MSD constraint is \textit{per-packet header parsing depth}. If an orchestration decision results in a SID list longer than $C_v^{msd}$, the hardware will be physically unable to parse the header, leading to an immediate binary failure in the data plane.

\textbf{C3: SLA Latency Constraint.} For a service class $k$, the total end-to-end latency $\mathcal{T}_r$ must be bounded by the class-specific threshold $\tau_k$:
\begin{equation}
\mathcal{T}_r = \sum_{(f_i, f_{i+1}) \in \mathcal{L}_r} L_{\mathcal{M}(f_i), \mathcal{M}(f_{i+1})} + \sum_{f_i} \delta_{proc}(\mathcal{M}(f_i)) \le \tau_k
\end{equation}
where $\delta_{proc}$ represents the dynamic processing delay which varies with the node's current MSD utilization.

\subsection{Multi-Objective Optimization Goal}
The objective of the JO-VPPM orchestrator is to maximize the network utility while satisfying all binary constraints. We formulate the joint objective as:
\begin{equation}
\max \text{Utility} = \omega_1 \mathcal{A}_{ratio} - \omega_2 \mathcal{B}_{lat} - \omega_3 \mathcal{C}_{mig}
\end{equation}
where $\mathcal{A}_{ratio}$ is the SFC acceptance ratio, $\mathcal{B}_{lat}$ is the cumulative SLA violation score, and $\mathcal{C}_{mig}$ is the migration cost (switching cost) incurred when relocating VNFs to maintain proactive resilience.
The \textbf{3S-COM} (Smart, Scalable, Secure) framework operates as a decentralized closed-loop system designed for high-availability core networks. The framework is structured into four distinct functional layers that synchronize to achieve hardware-aware, proactive orchestration.

\begin{enumerate}
    \item \textbf{Data-plane Telemetry and State Extraction:} This module serves as the primary sensor for the orchestrator. It continuously harvests fine-grained telemetry data from the substrate nodes $\mathcal{V}_s$, including CPU load, memory residency, and ingress MSD utilization. The telemetry data is normalized and transformed into a real-time network state tensor $\mathbf{X}_t$, which serves as the fundamental input for the subsequent AI layers.
    \item \textbf{Traffic Forecasting Adapter with Bi-GRU Readiness:} Unlike purely reactive systems that wait for congestion to occur, 3S-COM exposes a time-series forecasting adapter on incoming packet-per-second (PPS) telemetry. The deployed prototype supports loading a trained Bi-GRU checkpoint through \texttt{JO\_VPPM\_BIGRU\_MODEL\_PATH}; when no checkpoint is supplied, it uses a deterministic trend predictor to preserve a stable closed-loop alert path for testbed validation.
    \item \textbf{DGRL Orchestration (GAT):} The core intelligence module which maps the predicted state and current network topology onto an optimal orchestration action. Utilizing Graph Attention Networks, it prioritizes resource availability while respecting the hard spatial constraints of the network graph.
    \item \textbf{Stateless SRv6 Enforcement:} This layer translates the agent's placement or migration actions into standardized SRv6 instructions. It calculates the necessary SID list and encapsulates it within the IPv6 Segment Routing Header (SRH), enforcing the path across the P4 data plane without requiring flow-state maintenance in intermediate nodes.
\end{enumerate}

\subsection{Proactive Sensing: Bi-GRU-Ready Forecasting Adapter}
To fulfill the "Smart" requirement of 3S-COM, the prototype integrates a forecasting adapter into the backend control loop. The adapter is \textbf{Bi-GRU-ready}: it contains a Bidirectional Gated Recurrent Unit architecture and loads a trained checkpoint when \texttt{JO\_VPPM\_BIGRU\_MODEL\_PATH} is configured. In the current validation runs, no trained Bi-GRU checkpoint is required; the adapter falls back to a deterministic one-step trend forecast so that telemetry, forecast alerting, hysteresis gating, and DRL/MBB orchestration can be evaluated end-to-end.

The Bi-GRU architecture retained by the adapter follows the standard GRU formulation. Traditional RNNs suffer from vanishing gradients and an inability to perceive long-term temporal dependencies. The GRU architecture mitigates this via hidden state gating.

For an input sequence $\mathbf{x}_t$, the forward GRU cell calculates:
\begin{align}
r_t &= \sigma(\mathbf{W}_r \cdot [\overrightarrow{h}_{t-1}, x_t] + b_r) \quad \text{(Reset Gate)} \\
z_t &= \sigma(\mathbf{W}_z \cdot [\overrightarrow{h}_{t-1}, x_t] + b_z) \quad \text{(Update Gate)} \\
\tilde{h}_t &= \tanh(\mathbf{W}_{\tilde{h}} \cdot [r_t \ast \overrightarrow{h}_{t-1}, x_t] + b_{\tilde{h}}) \\
\overrightarrow{h}_t &= (1 - z_t) \ast \overrightarrow{h}_{t-1} + z_t \ast \tilde{h}_t
\end{align}
where $\sigma$ is the sigmoid activation function and $\ast$ denotes the Hadamard product. 

In the bidirectional implementation, the output hidden state $\mathbf{H}_t$ is the concatenation of the forward state $\overrightarrow{h}_t$ and the backward state $\overleftarrow{h}_t$:
\begin{equation}
\mathbf{H}_t = [\overrightarrow{h}_t \parallel \overleftarrow{h}_t]
\end{equation}
When a checkpoint is loaded, the adapter uses the Bi-GRU output as the predicted intensity $\hat{x}_{t+1}$. Without a checkpoint, the deterministic fallback extrapolates the most recent PPS slope. In both cases, the backend emits a forecast alert when the predicted PPS exceeds the configured threshold, and this alert is stored in the State Manager as a per-node proactive trigger.

\section{Deep Graph Reinforcement Learning: The JO-VPPM Engine}
To satisfy the requirements of topology-aware orchestration under hard data plane constraints (\textbf{RQ2}), we introduce the Deep Graph Reinforcement Learning (DGRL) engine. This module replaces standard topology-blind neural networks with a graph-centric intelligence.

\subsection{Markov Decision Process (MDP) Mapping}
The orchestration problem is modeled as a Markov Decision Process defined by the tuple $(\mathcal{S}, \mathcal{A}, \mathcal{P}, \mathcal{R}, \gamma)$.

\begin{itemize}
    \item \textbf{State Space ($\mathcal{S}$):} The observation vector follows the deployed testbed shape $N \times 6 + 13$. For a 10-node Vietnam Backbone, each node contributes six features: CPU utilization, RAM utilization, MSD used, MSD free, alert flag, and geo-latency context. The additional 13 global/request features encode service demand, SLA class, and orchestration context. This representation ensures the agent can perceive both local node saturation and global service requirements.
    \item \textbf{Action Space ($\mathcal{A}$):} We define a multi-discrete atomic action $a_t = [v_{place}, v_{route}]$, where the agent simultaneously selects the target VNF placement node and the routing/steering anchor. This avoids the two-stage flaw in which placement appears feasible locally but becomes invalid after SRv6 path expansion.
    \item \textbf{Reward Function ($\mathcal{R}$):} The scalar reward signal used to guide the policy toward feasibility and efficiency.
\end{itemize}

\subsection{Graph Attention Network (GAT) Mechanism}
Standard neural networks treat the 10-node network state as a flat vector, losing the critical spatial relationships between nodes. Our framework utilizes \textbf{Graph Attention Networks (GAT)} \cite{velivckovic2017graph} to extract topological features.

The input to each GAT layer is a set of node features, $\mathbf{h} = \{\vec{h}_1, \vec{h}_2, \dots, \vec{h}_n\}, \vec{h}_i \in \mathbb{R}^F$. The layer produces a new set of node features $\vec{h}_i' \in \mathbb{R}^{F'}$. 

A shared linear transformation, parametrized by a weight matrix $\mathbf{W} \in \mathbb{R}^{F' \times F}$, is applied to every node. We then compute a self-attention mechanism $a: \mathbb{R}^{F'} \times \mathbb{R}^{F'} \to \mathbb{R}$, which yields the attention coefficients:
\begin{equation}
e_{ij} = \text{LeakyReLU}\left(\vec{a}^T [\mathbf{W}\vec{h}_i \parallel \mathbf{W}\vec{h}_j]\right)
\quad \forall j \in \mathcal{N}_i
\end{equation}
where $\mathcal{N}_i$ is the neighborhood of node $i$ determined by the \textbf{Static Adjacency Matrix} $\mathcal{A}$. The coefficients are normalized across all neighbors using the softmax function:
\begin{equation}
\alpha_{ij} = \frac{\exp(e_{ij})}{\sum_{k \in \mathcal{N}_i} \exp(e_{ik})}
\end{equation}

To stabilize the learning process and capture multiple aspects of the topology (e.g., both latency-adjacent and capacity-adjacent relations), we utilize $K=4$ independent attention heads. The final output is the concatenation (or average) of the heads:
\begin{equation}
\vec{h}_i' = \sigma \left( \sum_{k=1}^K \alpha_{ij}^k \mathbf{W}^k \vec{h}_j \right)
\end{equation}

A fundamental engineer decision in JO-VPPM is the use of a \textbf{Static Adjacency Matrix}. While dynamic adjacency might seem intuitive, it disrupts the graph Fourier transform properties, leading to reward instability. Our GAT heads learn to extract dynamic metrics (MSD/CPU) through the node feature tensor while maintaining a consistent perception of the physical fiber distance through the static graph structure.

\subsection{Maskable PPO and Invalid Action Masking}
Traditional Reinforcement Learning relies on exploration-exploitation trade-offs where the agent learns from "mistakes" (penalties). However, in critical telecommunications infrastructure, an "illegal" placement (e.g., violating a hard MSD limit) results in an immediate service blackout.

To enforce \textbf{Hardware Safety}, we integrate \textbf{Invalid Action Masking} within the \textbf{Proximal Policy Optimization (PPO)} framework \cite{huang2022closer}. Let $\mathcal{Z}(s)$ be the set of feasible actions calculated by the Masking Layer based on current CPU and MSD residuals. The policy distribution $\pi_\theta(a|s)$ is modified before the softmax layer:
\begin{equation}
\hat{\pi}_\theta(a|s) = 
\begin{cases} 
\frac{\exp(z_a)}{\sum_{j \in \mathcal{Z}(s)} \exp(z_j)} & \text{if } a \in \mathcal{Z}(s) \\
0 & \text{otherwise}
\end{cases}
\end{equation}
where $z_a$ are the raw logits from the GAT-policy network. By setting the logits of unfeasible actions to $-\infty$, the agent's exploration is 100\% confined to the physically feasible space $\Omega$. This ensures that the JO-VPPM framework generates zero "Hardware-Invalid" decisions throughout its lifecycle, significantly outperforming standard "soft-penalty" RL agents.

\section{Adaptive Lagrangian Penalty and Reward Design}
The JO-VPPM agent optimizes for a multi-objective reward function $R_t$. While Invalid Action Masking handles local hardware availability, the global satisfaction of service-level agreements (SLA) requires an intelligent reward signal. We introduce the \textbf{Adaptive Lagrangian Penalty} to dynamically enforce these long-term constraints (\textbf{RQ1}).

\subsection{Mathematical Derivation of the Adaptive Penalty}
Standard RL models often struggle with fixed penalties, as a penalty that is too small leads to constraint violation, while a penalty that is too large leads to premature convergence to sub-optimal policies. We frame the orchestration as a constrained optimization problem:
\begin{align}
\max_{\theta} \quad & J(\pi_\theta) = \mathbb{E} [ \sum_{t=0}^T R_{base}(s_t, a_t) ] \\
\text{subject to} \quad & \mathbb{E} [ \sum_{t=0}^T C_{vio}(s_t, a_t) ] \le \Gamma
\end{align}
where $C_{vio}$ is the constraint violation cost and $\Gamma$ is the maximum tolerable violation threshold. The Lagrangian form of this objective is:
\begin{equation}
L(\theta, \lambda) = J(\pi_\theta) - \lambda \left( \mathbb{E} [ C_{vio} ] - \Gamma \right)
\end{equation}
In JO-VPPM, we implement an adaptive update law for the multiplier $\lambda$ based on the agent's empirical performance across a sliding window of $\Omega=20$ steps. Let $V_{rate}$ be the observed violation rate:
\begin{equation}
\lambda_{t+1} = \text{clip}\Big(\lambda_{t} + \eta \cdot (V_{rate} - \tau_{target}), \lambda_{min}, \lambda_{max} \Big)
\end{equation}
where $\eta$ is the learning rate of the dual multiplier. This ensures that $\lambda$ increases exponentially when violations are high, effectively "tilting" the reward landscape to favor safe actions, and decreases when the agent operates within the safe bounds, allowing it to focus on maximizing resource efficiency.

\subsection{Multi-Objective Reward Synthesis}
The composite reward function is designed to balance conflicting objectives: acceptance, latency, resource balance, and stability.
\begin{equation}
R_{total} = (R_{accept} \cdot \Psi_{res}) + B_{knap} + B_{core} - P_{swi} - P_{sla}
\end{equation}

\begin{itemize}
    \item \textbf{Knapsack Bonus ($B_{knap}$):} To prevent the agent from biased towards small, "easy" requests, we implement a bonus proportional to the request's resource density:
    \begin{equation}
    B_{knap} = \sigma \cdot \left( d_r^{cpu} \cdot d_r^{msd} \right)
    \end{equation}
    This encourages the agent to find feasible placements for "Elephant" flows, which are critical for high-throughput 5G services.
    \item \textbf{Core Hub Incentive ($B_{core}$):} Large requests are incentivized to reside on Core DCs (Hanoi, Da Nang, HCM) which possess higher MSD headroom and processing stability.
    \item \textbf{Switching Penalty ($P_{swi}$):} Triggered when the agent's decision at $t$ differs from $t-1$ for the same SFC, capturing the overhead of migration (FIB updates, state transfer).
    \item \textbf{SLA Violation Penalty ($P_{sla}$):} The adaptive penalty term derived from the Lagrangian multiplier:
    \begin{equation}
    P_{sla} = \lambda_t \cdot \mathbb{I}(\mathcal{T}_r > \tau_k) \cdot \frac{\mathcal{T}_r - \tau_k}{\tau_k}
    \end{equation}
    where $\mathcal{T}_r$ is the calculated total latency and $\tau_k$ is the SLA threshold.
\end{itemize}

\subsection{Resource Balancing and Entropic Regularization}
The final component $\Psi_{res}$ in the reward function ensures that resources are not disproportionately consumed at a single hub. It is calculated as the inverse variance of the CPU utilization across the 10 nodes. Furthermore, the PPO objective includes an entropy term $H(\pi_\theta)$ to maintain exploration:
\begin{equation}
L^{PPO}(\theta) = \hat{\mathbb{E}}_t [ L^{CLIP}(\theta) + c_1 L^{VF}(\theta) + c_2 H(\pi_\theta) ]
\end{equation}
The integration of GAT-based feature extraction with this adaptive reward structure is evaluated in the completed stress benchmark on the Vietnam, NSFNET, and GEANT2 topologies.

\section{Algorithm Complexity and Theoretical Scalability}
To evaluate the practical feasibility of JO-VPPM in carrier-grade 5G networks, we analyze the computational complexity of the orchestration engine.

\subsection{Computational Complexity of JO-VPPM}
The runtime performance is dominated by the inference phase of the Graph Attention Network. For a substrate network with $N = |\mathcal{V}|$ nodes and $M = |\mathcal{E}|$ edges, the complexity of a single GAT layer with $K$ attention heads and $F'$ output features is:
\begin{equation}
\mathcal{O}(N \cdot F \cdot F' \cdot K + M \cdot F' \cdot K)
\end{equation}
Since the number of nodes in a typical national backbone (e.g., Vietnam Backbone) is relatively small ($N \approx 10-100$), and the adjacency matrix is sparse, the GAT inference complexity remains practical for online orchestration. This contrasts sharply with traditional Integer Linear Programming (ILP) solvers, which exhibit exponential complexity $\mathcal{O}(2^N)$ and become intractable for large-scale geo-distributed deployments.

\subsection{Scalability via Static Graph spectral Stability}
The decision to utilize a \textbf{Static Adjacency Matrix} (\textbf{RQ2}) significantly enhances the framework's scalability. By decoupling the static physical topology from the dynamic node feature updates, the GAT parameters $W^k$ remain valid even as traffic intensity fluctuations occur. This prevents the need for frequent re-training (retraining overhead), allowing the JO-VPPM agent to maintain high accuracy across varying load profiles without a proportional increase in computational cost.

\subsection{Memory Footprint and Hardware Offloading}
The memory overhead of the JO-VPPM agent is characterized by the storage of the GAT weights and the state tensor $\mathbf{X}_t$. Given the compact $N \times 6 + 13$ observation structure and the small size of national backbone graphs, the total footprint is less than 50MB, making it suitable for deployment on edge compute nodes or integration into the Network Functions Virtualization Infrastructure (NFVI) control plane. Future implementations could potentially offload the GAT matrix multiplications directly onto \textbf{NVIDIA BlueField-3 DPUs} or programmable switch control units to further reduce the orchestration latency to the microsecond range.

\section{System Operations and SFC Lifecycle Management}
To bridge the gap between AI decision-making and data plane enforcement (\textbf{RQ3}), we formalize the operational lifecycle of a service request within the JO-VPPM framework.

\subsection{Placement to Path Mapping and SRv6 Embedding}
The joint optimization process produces a node assignment $\mathbf{v} = \{v_1, v_2, \dots, v_m\}$. However, for data plane steering, this must be transformed into a sequence of hop-by-hop instructions. Given the adjacency matrix $\mathcal{A}$, the shortest path $\mathcal{P}_{i, i+1}$ between any two scheduled nodes $v_i$ and $v_{i+1}$ is computed via the Dijkstra algorithm:
\begin{equation}
\mathcal{P}_{i, i+1} = \arg \min_{P \in \Gamma(v_i, v_{i+1})} \sum_{e \in P} L_e
\end{equation}
where $L_e$ is the link latency. The resulting physical path is then mapped to an SRv6 Segment List $\mathcal{S} = [SID_{v_1}, SID_{f_1}, SID_{v_2}, SID_{f_2}, \dots]$. 

The enforcement module ensures that for every ingress node $v_{ingress}$, the encapsulated SRH header does not exceed the MSD limit $C_{v_{ingress}}^{msd}$. If $\text{len}(\mathcal{S}) > C_{v_{ingress}}^{msd}$, the action is removed from the feasible action set before policy sampling. If all candidates are removed, the request is rejected with \texttt{409 NO\_SAFE\_ACTION}. This behavior is Smart Admission Control, not a deployment error: it protects the data plane from unsafe SRv6 headers instead of bypassing the hardware constraint with Binding SID compression.

\subsection{Proactive Migration Triggering Logic}
A core novelty of JO-VPPM is its ability to migrate VNFs pre-emptively. Let $\mathcal{X}(t)$ be the current traffic intensity and $\hat{\mathcal{X}}(t+1)$ be the one-step-ahead prediction from the forecasting adapter. In the deployed backend, the prediction is produced either by a loaded Bi-GRU checkpoint or by the deterministic trend fallback.

The migration alert for a node is triggered if:
\begin{equation}
\hat{\mathcal{X}}(t+1) \ge \Theta_{pps}
\end{equation}
where $\Theta_{pps}$ is configured by \texttt{JO\_VPPM\_FORECAST\_PPS\_THRESHOLD} and defaults to 800 PPS in the current prototype. When the alert is active, the Hysteresis Gate engages DRL mode; if an existing VNF is present on the selected node, the orchestrator initiates the Make-Before-Break sequence, otherwise it deploys the new VNF through the normal Tekton lifecycle.

\subsection{Algorithm Stability and Training Dynamics}
The convergence of the JO-VPPM agent is governed by the consistency of the value function $V(s)$. By utilizing a \textbf{Static Adjacency Matrix}, we ensure that the structural embeddings produced by the GAT layers remain invariant to load fluctuations. This architectural choice prevents the "feature drift" common in dynamic graph reinforcement learning, allowing the PPO agent to achieve a stable Explained Variance ($\approx 0.42$) even in environments with highly stochastic traffic surges.

\section{Stress Scenario Design}

Three stress scenarios are used throughout the algorithm benchmark:

\begin{itemize}
    \item \textbf{Elephant Stress:} a heavy-tail demand pattern where a small number of large flows consume disproportionate CPU and path resources. This scenario tests whether the policy can avoid placing large chains on edge nodes that lack both compute headroom and MSD budget.
    \item \textbf{Burst Surge:} a sudden traffic surge that compresses many requests into a short interval. This scenario tests admission behavior under abrupt load changes, where myopic algorithms tend to overfill attractive core nodes early.
    \item \textbf{Chaos Stress:} a mixed adversarial setting combining high demand variance, diverse SLA classes, and difficult source-destination pairs. This is the hardest scenario because both compute scarcity and path-depth scarcity appear simultaneously.
\end{itemize}

\section{Hardware-in-the-Loop Testbed Implementation}
\label{chap:testbed}

This chapter details the realization of the JO-VPPM orchestrator from mathematical simulation to a tangible data plane. The latest 3S-COM testbed implements a 10-node Vietnam Backbone with MicroK8s-based VNF orchestration, Tekton lifecycle automation, Mininet-to-Kubernetes connectivity, CPU-pinned BMv2 P4 switches, and an SDN controller exposing SRv6 steering APIs on port \texttt{8765}. The purpose of this testbed is not merely to visualize AI decisions, but to validate hardware-aware admission control and prepare the execution path for Make-Before-Break migration without violating SRv6 MSD limits.

\subsection{Overall Testbed Architecture}
The testbed is structured across three distinct functional tiers:
\begin{enumerate}
    \item \textbf{Tier 1 -- Data Plane (Mininet + BMv2):} Mininet instantiates the 10-node Vietnam Backbone topology. Each BMv2 switch runs a compiled profile of \texttt{srv6\_basic.p4}, with \texttt{MAX\_SID\_DEPTH} fixed at compile time for the node's MSD class. BMv2 containers are pinned to CPU cores via \texttt{--cpuset-cpus} to reduce scheduler-induced jitter.
    \item \textbf{Tier 2 -- Control Plane \& AI Inference:} The FastAPI backend hosts the RuleDRL orchestrator, loads \texttt{dgrl\_v11\_final\_vietnam.zip} with \texttt{vec\_normalize\_v11\_vietnam.pkl}, and maintains the thread-safe state manager. The SDN controller receives steering requests and programs the BMv2 testbed through the available runtime interface. Packet classification is intentionally simplified in the prototype; the critical behavior demonstrated is SRv6 steering visibility and MSD-safe orchestration.
    \item \textbf{Tier 3 -- NFV Lifecycle \& Visualization:} MicroK8s runs VNFs in namespace \texttt{core-router}. Tekton handles lifecycle tasks, while the React dashboard displays topology, VNF placement, SRv6 path status, and admission-control outcomes.
\end{enumerate}

Early prototypes used NodePort exposure because it provides a simple and debuggable path from Mininet hosts to Kubernetes services. The design explicitly removes \texttt{iptables MASQUERADE}; instead, per-host return routes ensure that VNF Pods observe the original host IP address. This matters for SFC integrity because security and DDoS-analysis functions must see the real traffic source rather than a NATed node address.

The resulting path connects the two worlds without treating Mininet/P4 and Kubernetes as independent demonstrations. Traffic generated by Mininet hosts can traverse the P4 topology, reach the exposed VNF service, and return through deterministic routes.

\subsection{Realizing the Data Plane: Mininet and P4 (BMv2)}

\textbf{Physical Latency Emulation:} The Linux \texttt{tc netem} utility injects propagation delays into Mininet virtual links, directly mapping to the Haversine distance matrix.

\textbf{P4 Programming for SRv6 \& MSD Limits:} The data plane logic in \texttt{srv6\_basic.p4} \cite{stockmayer2020p4sfc} implements basic SRv6 forwarding and hard MSD enforcement:
\begin{itemize}
    \item \textbf{Parser-level hard limit:} \texttt{MAX\_SID\_DEPTH} bounds the SID array at compile time. If a packet carries more SIDs than the profile allows, the parser raises the violation condition and the ingress control drops the packet.
    \item \textbf{SRv6 local SID processing:} the \texttt{srv6\_local\_sid} table advances the segment list for local SIDs and supports standard SRv6 forwarding behavior.
    \item \textbf{IPv6 routing:} the \texttt{routing\_v6} table forwards packets toward the next hop selected by the controller.
    \item \textbf{Visibility:} \texttt{msd\_violation\_counter} records hard drops and is exposed.
\end{itemize}

There is deliberately no Binding SID table in the P4 pipeline. The testbed uses P4 to enforce the physical MSD boundary, while the backend and AI layer are responsible for avoiding unsafe SID stacks before packets reach the data plane. This preserves the scientific novelty of Action Masking: the orchestrator must solve the hardware-constrained placement/routing problem rather than relying on a data-plane escape hatch.

\subsection{AI-SDN Bridge: Inference Engine and Controller}

\subsubsection{Hybrid Decision Pipeline}
The testbed does not call the DRL model blindly for every request. It uses a hybrid gate that selects between a fast deterministic heuristic and the JO-VPPM policy according to the current telemetry state. Under stable traffic, the heuristic path keeps decision latency low and avoids unnecessary model invocations. When load, alert, or migration pressure crosses the configured threshold, the Hysteresis Gate switches to the DGRL path so that the placement and routing decision can use the graph-aware policy.

The output of both paths is passed through the same Smart Admission Control block. This final gate validates CPU, RAM, alert constraints, and path-aware MSD before any Kubernetes or SDN action is issued. Therefore, the hybrid mechanism is not a fallback that bypasses safety; it is a runtime selector whose outputs are all checked by the same hardware-aware admission layer.

The state manager prepares the deployed observation vector $N \times 6 + 13$ and applies the Hysteresis Gate: heuristic mode is used during stable load, while DGRL mode activates above the engage threshold ($0.45$) or when an alert flag is present. The release threshold ($0.35$) prevents rapid oscillation between modes.

If no placement-routing pair is safe, the API returns \texttt{409 NO\_SAFE\_ACTION}. This is a correct protection outcome, not an error condition. The dashboard and benchmark therefore distinguish rejected unsafe requests from admitted service failures.

\subsection{Testbed Benchmark Scenarios}
To validate the complete control loop on real hardware, five scenarios were executed on the 10-node Vietnam hardware-in-the-loop testbed. These scenarios are stored under:
\begin{center}
\texttt{results/benchmark\_testbed/20260517\_201632/scenarios}
\end{center}

The testbed benchmark differs from the pure algorithm benchmark in one important way: unsafe choices are not treated as admitted service actions. The runtime can reject them as \texttt{NO\_SAFE\_ACTION}, and the P4 data plane still exposes MSD drops as a final hardware counter. Therefore, a low acceptance rate in the hardest scenarios means that the physical system has reached safe capacity, not that unsafe packets were forwarded.

\subsubsection{Scenario Definitions}

\begin{itemize}
    \item \textbf{Normal Load:} a small baseline workload of 34 requests. It verifies that the end-to-end path, Kubernetes deployment, SRv6 steering, and telemetry collection work under non-stressed conditions.
    \item \textbf{Elephant Heavy-Tail:} 93 requests with heavy-tail resource demand. It models a few large flows that consume much more CPU and path budget than ordinary traffic.
    \item \textbf{Topology and Physics Stress:} 118 requests emphasizing geographically difficult source-destination pairs. It stresses long paths, larger SID lists, and edge/core MSD asymmetry.
    \item \textbf{DDoS and Make-Before-Break:} 113 requests with an overload pattern that triggers the proactive migration path. This scenario validates the hybrid gate, alert handling, and steering workflow under burst pressure.
    \item \textbf{Chaos:} 240 mixed requests combining heavy-tail demand, topology stress, and saturation. It is the harshest testbed scenario and primarily evaluates safe rejection behavior.
\end{itemize}

\subsubsection{Testbed Results and Interpretation}

Under Normal Load, the system is not capacity-bound. JO-VPPM, Hybrid Runtime, Heuristic, and Greedy all accept \textbf{100\%} of requests with \textbf{0\%} MSD violations. Decoupled AI accepts \textbf{94.1\%} and already records \textbf{5.9\%} MSD violations, showing that separating placement and routing can violate hardware constraints even before stress begins.

In Elephant Heavy-Tail, JO-VPPM accepts \textbf{71.0\%} of requests with \textbf{0\%} MSD violations. Hybrid Runtime reaches \textbf{75.3\%} because it can use the heuristic path when deterministic admission is sufficient. Greedy accepts only \textbf{59.1\%} and produces \textbf{19.4\%} MSD violations, while Decoupled AI falls to \textbf{52.7\%} acceptance with \textbf{22.6\%} MSD violations. This scenario confirms that large flows require joint compute-path reasoning.

Topology and Physics Stress is dominated by long paths. JO-VPPM and Hybrid Runtime both accept \textbf{21.2\%} with \textbf{0\%} MSD violations. Greedy appears to match the same acceptance rate, but this is misleading because it also produces \textbf{78.8\%} MSD violations. Decoupled AI is worse, accepting only \textbf{9.3\%} while violating MSD in \textbf{90.7\%} of requests. The testbed therefore shows why raw acceptance alone is not a valid metric for SRv6-constrained orchestration.

In DDoS and Make-Before-Break, Hybrid Runtime accepts \textbf{24.8\%} and JO-VPPM accepts \textbf{23.0\%}, both with \textbf{0\%} MSD violations. The Hybrid Runtime records nine migration triggers, demonstrating that the alert-driven gate is exercised. Greedy reaches \textbf{25.7\%} acceptance but at the cost of \textbf{69.0\%} MSD violations; Decoupled AI accepts \textbf{18.6\%} with \textbf{77.9\%} MSD violations. Thus, the slight admission advantage of Greedy is not deployable on the P4/SRv6 testbed.

Chaos is the saturation case. JO-VPPM accepts \textbf{10.0\%}, Hybrid Runtime accepts \textbf{8.3\%}, Heuristic and Greedy accept \textbf{7.9\%}, and Decoupled AI accepts \textbf{5.8\%}. The key result is that JO-VPPM, Hybrid Runtime, and Heuristic all maintain \textbf{0\%} MSD violations, while Greedy and Decoupled AI generate \textbf{79.2\%} and \textbf{81.3\%} MSD violations. In this regime, safe rejection is the correct behavior because most candidate requests cannot be admitted without exceeding either compute or SID-depth limits.

Across all five scenarios, the testbed validates the deployment claim that JO-VPPM and the hybrid runtime can preserve \textbf{0\% admitted MSD violations}. The benchmark also explains why the algorithm-only stress figures may still show unsafe accounting: the live testbed converts unsafe candidates into admission rejections before they become data-plane behavior.

\subsection{Make-Before-Break Migration Workflow}
This scenario defines the validation workflow for proactive Make-Before-Break migration. The current implementation separates replacement creation, traffic steering, and old-instance deletion, but the live zero-downtime demonstration has not yet been fully validated. Therefore, this thesis treats the sequence below as the intended execution path, while a final zero-downtime claim remains dependent on a dedicated packet-capture or TCP continuity run:
\begin{enumerate}
    \item \textbf{Traffic Generation:} A continuous TCP ``Elephant'' flow is generated with \texttt{iperf3}/\texttt{Scapy} through a VNF instance initially placed on the northern part of the topology.
    \item \textbf{Alert Trigger:} A UDP burst is used to emulate overload, set the alert flag, and push the Hysteresis Gate into DGRL mode.
    \item \textbf{Sequential Make-Before-Break Procedure:}
    \begin{itemize}
        \item \textit{Make:} Tekton creates a replacement VNF on the target Kubernetes node selected by the AI-to-K8s mapping.
        \item \textit{Wait:} Backend waits until Kubernetes reports the replacement Deployment Ready.
        \item \textit{Translate:} Backend translates the replacement Pod/service endpoint into a hardware-safe SRv6 SID list.
        \item \textit{Steer:} SDN controller updates BMv2 forwarding tables and reports \texttt{confirm\_steer\_done=true} when the steering update is complete.
        \item \textit{Break:} Backend is allowed to delete the old VNF \textbf{only after} steer confirmation. The deletion of the old VNF (Break) must never be triggered until the SDN Controller has confirmed that the new SRv6 routing rules are fully installed.
    \end{itemize}
\end{enumerate}

\subsection{Phase Validation Summary}
The current testbed has completed seven implementation phases. The most important validation outcomes are summarized as follows:
\begin{itemize}
    \item \textbf{K8s and VNF foundation:} MicroK8s namespace \texttt{core-router}, local registry, vVOC image, RBAC, and readiness integrity are operational.
    \item \textbf{Lifecycle orchestration:} Tekton supports Make-Before-Break through a single-VNF migration pipeline, separating Pod lifecycle from SDN steering.
    \item \textbf{Mininet-K8s connectivity:} \texttt{br-k8s-mn} provides L2-transparent connectivity without MASQUERADE, preserving source IP visibility.
    \item \textbf{P4 SRv6 data plane:} \texttt{srv6\_basic.p4} enforces compile-time MSD limits, exposes \texttt{msd\_violation\_counter}, and runs in CPU-pinned BMv2 containers.
    \item \textbf{Hybrid AI orchestration:} Hysteresis-controlled RuleDRL uses Heuristic mode under stable load and DGRL mode under stress or alert conditions. The deployed backend requires the real JO-VPPM model and scaler; model-loading failure is treated as a runtime failure rather than silently falling back to Shadow Mode.
    \item \textbf{Geo-distributed deployment:} AI node IDs are mapped to Kubernetes hostnames and injected through \texttt{nodeSelector}.
    \item \textbf{10-node topology validation:} The Phase 7 topology assigns dedicated Thrift ports \texttt{19091--19100}, supports dynamic CPU pinning, and passes the full smoke-test suite for the Vietnam 10-node backbone.
\end{itemize}

\chapter{Conclusion and Future Work}
\label{chap:conclusions}

\section{Technical Contributions}
This research addressed the critical challenge of hardware-aware Service Function Chaining (SFC) in geo-distributed 5G core networks. By proposing the \textbf{JO-VPPM} framework and its underlying \textbf{3S-COM architecture}, the thesis connects AI-based orchestration with the physical limits of SRv6/P4 data planes. The final contributions are synthesized from the identified research gaps and research questions as follows:
\begin{enumerate}
    \item \textbf{Hardware-Constrained JO-VPPM Formulation:} The thesis formulates joint VNF placement, routing, and proactive migration under explicit compute, latency, and Maximum Segment Depth (MSD) constraints. This directly addresses the hardware--data plane disconnect by treating MSD as a hard binary boundary rather than a soft reward penalty. A candidate action is feasible only if the resulting SRv6 segment list can be parsed by the selected programmable switch; otherwise, it is masked or rejected through Smart Admission Control.
    \item \textbf{Topology-Aware Safe Reinforcement Learning:} The proposed DGRL agent combines Graph Attention Networks (GAT), Static Adjacency modeling, MaskablePPO, Invalid Action Masking, and an Adaptive Lagrangian Penalty. This answers the topology-blindness and graph-instability gaps by giving the policy a stable geographical view of the substrate network while preserving hard safety constraints during action selection.
    \item \textbf{Closed-Loop Proactive Orchestration Architecture:} The 3S-COM architecture integrates telemetry, forecasting readiness, hysteresis-based runtime mode selection, JO-VPPM inference, Smart Admission Control, and SRv6 steering. This contribution moves SFC orchestration beyond purely reactive placement by providing an execution path for proactive migration decisions under geo-distributed latency and resource pressure.
    \item \textbf{Stress-Oriented Multi-Topology Evaluation:} The completed benchmark evaluates JO-VPPM on Vietnam, NSFNET, and GEANT2 under Elephant, Burst Surge, and Chaos scenarios. Across all nine stress evaluations, JO-VPPM achieves the strongest acceptance behavior and reward trend compared with Traditional Greedy and Decoupled AI, while consistently reducing MSD-unsafe accounting. This provides the empirical answer to the performance-oriented research question.
    \item \textbf{Hardware-in-the-Loop Runtime Validation and Make-Before-Break Sequencing:} The testbed integrates MicroK8s, Tekton, Mininet, BMv2 P4 switches, SRv6 steering, FastAPI orchestration, and a telemetry-driven dashboard. In the five executed testbed scenarios, JO-VPPM and the Hybrid Runtime maintain \textbf{0\% admitted MSD violations}, showing that unsafe algorithmic candidates can be converted into explicit admission rejections before reaching the data plane. The implementation also defines the Make-Before-Break control sequence: create the replacement VNF, wait for readiness, translate the new endpoint into an SRv6-safe path, steer traffic, and delete the old VNF only after controller confirmation. A dedicated packet-continuity run remains necessary before making a final zero-downtime claim.
\end{enumerate}

\section{Future Research}
The evolution of 6G networks and Open RAN (O-RAN) presents exciting opportunities to expand the 3S-COM architecture:
\begin{itemize}
    \item \textbf{Cross-Topology Generalization:} The current stress benchmark validates Vietnam, NSFNET, and GEANT2 separately. A future study should quantify transfer learning and domain adaptation across topologies without retraining from scratch.
    \item \textbf{Multi-Agent DRL / Federated Learning:} To scale orchestration across international backbone boundaries with thousands of nodes, transitioning from a Centralized single-agent to a Decentralized Multi-Agent PPO (MAPPO) architecture is a crucial next step. Each regional controller would train locally and share gradient updates via Federated Averaging, eliminating the single-point-of-failure and computation bottleneck of centralized inference. This aligns with emerging research on securing and federating intelligent orchestration for 6G and IoT environments \cite{kantarci2025federated, wang2022securing}.
    \item \textbf{Hardware Offloading:} Future implementations could offload the GAT matrix multiplications directly onto \textbf{NVIDIA BlueField-3 DPUs} or P4-programmable smartNICs to achieve microsecond-level decision latency, fully closing the gap between AI inference and wire-speed data plane enforcement.
\end{itemize}

\chapter{DGRL Policy Architecture}
\label{appendix:neural_arch}
The JO-VPPM agent uses a GAT-based actor-critic policy built with PyTorch and deployed through the FastAPI inference engine. In the implementation, the policy wrapper is named \texttt{GNNActorCriticPolicy}, but the graph encoder inside that policy is a two-layer Graph Attention Network (GAT). The production testbed loads the trained Vietnam model artifact \texttt{dgrl\_v11\_final\_vietnam.zip} together with the normalization statistics in \texttt{vec\_normalize\_v11\_vietnam.pkl}.

The policy receives a topology-specific adjacency matrix that is fixed for each inference run, together with dynamic node features. The adjacency matrix preserves the geographical structure of the selected substrate graph, while the feature tensor carries changing runtime information such as CPU pressure, MSD headroom, and alert state.

\begin{itemize}
    \item \textbf{Action representation:} the agent selects a joint placement-routing decision rather than separating placement from path feasibility.
    \item \textbf{Hard constraints:} CPU/RAM capacity and SRv6 MSD feasibility are enforced by invalid action masking before policy sampling.
    \item \textbf{Soft constraints:} latency and SLA pressure are handled through the adaptive Lagrangian penalty in the reward function.
    \item \textbf{No-safe-action behavior:} if all candidate actions are masked, the runtime returns \texttt{409 NO\_SAFE\_ACTION}; this is an explicit admission-control outcome, not a model crash.
\end{itemize}

The traffic forecasting component described in Chapter \ref{chap:method} is not part of the trained DGRL policy artifact. The current prototype is \textbf{Bi-GRU-ready}: it can load a trained Bi-GRU checkpoint when \texttt{JO\_VPPM\_BIGRU\_MODEL\_PATH} is supplied, but the validation runs use a deterministic one-step trend fallback. Therefore, the reported DGRL benchmark results should be attributed to the JO-VPPM GAT/MaskablePPO policy and hardware-aware admission logic, not to a separately trained Bi-GRU forecaster.
