# Live HIL E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce reproducible evidence for single-VNF operation, ordered multi-VNF traversal, and migration continuity on the existing live testbed.

**Architecture:** Keep live state intact while adding read-only inventory and validation first. Add isolated, bounded packet experiments with request/packet identity, then perform one post-restart validation only after startup state and rollback are verified. Keep pair-level policy claims separate from testbed chain evidence.

**Tech Stack:** Python 3.11, pytest, Kubernetes/Tekton, Mininet, BMv2 P4, Linux SRv6, tcpdump.

**Spec:** `docs/superpowers/specs/2026-11-24-hil-e2e-completion-design.md`

## Global Constraints

- Preserve all existing VNFs, rules, reservations, and unrelated services.
- No broad cleanup, ledger reset, backend/Mininet restart, or firewall mutation without a concrete recovery path and live preflight.
- Every paper claim must be supported by request-correlated raw evidence and explicit denominators.
- The current HARP policy is pair-level; chain experiments cannot establish full-chain policy selection.

## Review Focus

- A failed read-only command must fail preflight, not silently produce an empty inventory.
- Current backend image and local source may differ; record hashes and prevent mixed-version attribution.
- A packet received only by the final VNF does not prove ordered traversal.
- A migration with changed Pod IP may lose in-flight packets despite correct control-plane ordering.
- A successful one-time firewall fix may disappear on reboot; verify persistence separately.
